### 第 5 页：三重局限 + 竞品差异化

- **标题**：现有工具解决了"写代码"，没解决"团队交付"
- **三重局限**：
  1. **协作碎片化**：本地 IDE / CLI，代码与素材分散，多人协作靠 Git + 微信
  2. **资源激活门槛高**：通用大模型只能输出代码片段，不能把沉睡的课件/教案系统重构为应用
  3. **长程任务不可持续**：设备关机，任务中断，复杂项目无法持续迭代
- **我们不是谁**：
  - 不是 **Cursor / Claude Code / Codex**（桌面/CLI、闭源、部分已断供）
  - 不是 **Kimi / DeepSeek / 通义千问 / 豆包**（对话式顾问，缺工程操作与项目治理）
  - 不是 **Trae / Qoder**（桌面 IDE，缺服务器端长程 Agent）
- **我们的定位**：
  > 面向团队的、服务器端常驻的、具备资源重构与协同治理能力的 **Web 平台**。
- **视觉建议**：中央放"猹询码"，四周用箭头标注差异化对比
- **演讲时长**：20 秒
- **时事结合**：可在"海外竞品"旁加一个红色小标签："Fable 5 刚被美国政府全球禁用"

## 六、评委可能提问与回答准备

### Q1：你们和 Kimi / DeepSeek 是什么关系？

**回答**：我们不是替代 Kimi 或 DeepSeek，而是在它们之上做一个**平台层**。Kimi 是优秀的国产大模型，我们基于开源的 Kimi CLI 做二次开发与架构重构，但 Kimi 本身是对话式助手，缺少工程操作、项目治理和团队协作能力。猹询码把这些能力补齐，形成"模型 + 平台"的完整闭环。

### Q2：Fable 5 被封禁和你们项目有什么关系？

**回答**：Fable 5 事件恰恰说明了两点：第一，海外最强闭源模型存在**政策断供风险**；第二，自主可控不是可选项，而是必选项。我们的平台从底座开始就采用国产模型矩阵，并持续接入 Kimi、GLM 等国产开源模型，降低对单一海外闭源生态的依赖。

### Q3：你们的"资源重构"具体怎么做？

**回答**：资源重构是指把沉淀的文档、课件、教案、语料库等数字素材，通过 Agent 自动解析、需求抽取、结构生成、代码生成、部署上线，最终变成可运行的 Web 应用或智能体。例如外国语学院的教学网页，就是把课程单元素材导入后，经过三轮自然语言迭代生成的。

### Q4：服务器端常驻会不会成本很高？

**回答**：我们目前部署在阿里云轻量服务器，先行版本已验证成本可控。大创经费主要用于服务器、域名和云资源。未来会提供容器化私有化部署方案，高校和企业可以按需部署在自己的服务器上。

### Q5：你们说的"自进化"具体指什么？

**回答**：自进化是指团队使用猹询码平台来协同开发猹询码自身。平台提供代码生成、自动部署、Git 同步、操作审计等能力，团队迭代自己的平台时，这些能力会同步增强平台本身，形成正反馈循环。
