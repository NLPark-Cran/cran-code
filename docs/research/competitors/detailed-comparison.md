# 猹询码 vs 核心竞品详细对比

> 调研日期：2026-06-08  
> 对比维度：技术架构、功能特性、用户体验、商业模式、与猹询码的竞合关系

---

## 一、Claude Code vs 猹询码

### 产品哲学对比

| 维度 | Claude Code | 猹询码 |
|------|-------------|--------|
| 核心理念 | "终端就是我的 IDE" | "服务器端就是我的开发中枢" |
| 架构假设 | 开发者在本地工作，AI 在终端辅助 | 开发者在任何设备工作，AI 在服务器常驻 |
| 交互方式 | 终端对话（TUI） | Web GUI + 终端 + 协同编辑 |

### 功能详细对比

| 功能 | Claude Code | 猹询码 |
|------|-------------|--------|
| 代码补全 | ❌ 不支持 | ⚠️ 通过 Monaco Editor 支持 |
| 多文件编辑 | ✅ 强（Agent 模式） | ✅ 支持 |
| Shell 命令执行 | ✅ 原生支持 | ✅ Web 终端支持 |
| 持久化长任务 | ⚠️ 需保持终端开启 | **✅ 服务器 24h 运行** |
| Git 集成 | ✅ Git Worktree | ✅ Git 集成 |
| 团队协作 | ❌ 无 | **✅ 多人协同编辑** |
| Web 前端 | ❌ 无 | **✅ React 19 SPA** |
| 项目管理 | ❌ 无 | **✅ 团队/项目/成员管理** |
| 文件管理 | ⚠️ 命令行操作 | **✅ 可视化文件树** |
| 域名/部署 | ❌ 无 | **✅ 二级域名一键申请** |
| MCP 支持 | ✅ 第一公民 | ✅ 已移植 |
| Skills 支持 | ✅ SKILL.md | ✅ 兼容 |
| 模型选择 | ❌ 仅 Claude | **✅ Kimi + MiniMax 多模型** |
| 开源协议 | 自定义 | 基于 MIT/Apache（待确认）|
| 私有化部署 | ⚠️ 间接 | **✅ 完全私有** |

### 结论

Claude Code 是"最强单机终端 Agent"，但**不具备服务器常驻、团队协作、Web 可视化**能力。猹询码补足了这些空白，形成差异化。

## 二、Cursor vs 猹询码

### 产品哲学对比

| 维度 | Cursor | 猹询码 |
|------|--------|--------|
| 核心理念 | "AI 优先的 IDE" | "AI 优先的服务器端开发平台" |
| 形态 | 桌面应用（Fork VS Code）| Web 应用 + 服务器后端 |
| 目标用户 | 专业开发者 | 团队开发者 + 文科生 |

### 关键差异

| 维度 | Cursor | 猹询码 |
|------|--------|--------|
| 安装方式 | 下载安装桌面应用 | 浏览器访问网址 |
| 设备限制 | 需安装到每台电脑 | 任何有浏览器的设备 |
| 操作系统 | macOS/Windows/Linux | 全平台（浏览器）|
| 关机影响 | ❌ 关机即中断 | **✅ 服务器持续运行** |
| 协作编辑 | ⚠️ 有限（Composer） | **✅ Yjs 实时代码协同** |
| 中文适配 | ⚠️ 一般 | **✅ 国产模型深度适配** |
| 数据隐私 | ❌ 上传 Cursor 服务器 | **✅ 完全本地/自有服务器** |
| 断供风险 | ⚠️ 已对中国模型断供 | **✅ 国产自主可控** |
| 费用 | $20/月 | **✅ 开源免费** |
| 终端能力 | ⚠️ 内置终端有限 | **✅ 完整 Web 终端** |
| 域名管理 | ❌ 无 | **✅ 二级域名一键上线** |

### 结论

Cursor 是"最强桌面 AI IDE"，但**受限于桌面形态、闭源风险、断供隐患**。猹询码以"服务器端 + Web + 国产"三条线形成完全差异化。

## 三、Trae vs 猹询码

### 产品哲学对比

| 维度 | Trae | 猹询码 |
|------|------|--------|
| 厂商 | 字节跳动 | NLPark-Cran（学生团队）|
| 定位 | 国内首个 AI 原生 IDE | 开源服务器端 Agentic Coding 平台 |
| 资源 | 大厂背书，无限算力 | 学生团队，开源社区 |

### 关键差异

| 维度 | Trae | 猹询码 |
|------|------|--------|
| 形态 | 桌面 IDE | Web + 服务器 |
| 开源 | ❌ 闭源 | **✅ 开源** |
| 自主权 | 受字节战略影响 | **✅ 完全自主** |
| 长程任务 | ❌ 本地运行 | **✅ 服务器常驻** |
| 协作深度 | ✅ 企业版 | ✅ 原生支持 |
| 目标用户 | 专业开发者 | **✅ 文科生/学生团队** |
| 品牌独立性 | 字节产品 | **✅ 独立开源品牌** |

### 结论

Trae 是"国产 Cursor"，大厂资源碾压，但**闭源、桌面形态、不面向文科生**。猹询码以"开源 + 服务器端 + 文科生友好"错位竞争。

## 四、MonkeyCode vs 猹询码

### 产品哲学对比

| 维度 | MonkeyCode | 猹询码 |
|------|------------|--------|
| 定位 | 企业级开源 AI 编程助手 | 面向团队的 AI 编程协作平台 |
| 形态 | VS Code 插件 + 服务器后端 | Web 前端 + 服务器后端 |
| 目标 | 替代 Cursor Teams | 替代完整开发工具链 |

### 关键差异

| 维度 | MonkeyCode | 猹询码 |
|------|------------|--------|
| 前端形态 | VS Code 插件 | **✅ 独立 Web 应用** |
| 非开发者友好 | ❌ 需 VS Code | **✅ 浏览器即用** |
| 协同编辑 | ❌ 无 | **✅ Monaco + Yjs** |
| 项目管理 | ⚠️ 有限 | **✅ 完整团队/项目/权限** |
| 域名部署 | ❌ 无 | **✅ 二级域名上线** |
| 运维功能 | ❌ 无 | **✅ 文件管理+终端** |
| 学术背景 | 纯工程 | **✅ 计算语言学+语言哲学** |

### 结论

MonkeyCode 是"开源版 Cursor Teams"，猹询码是"Web 版开发平台"，形态和用户群体不同。

## 七、猹询码的竞争策略建议

### 1. 错位竞争（申报书核心论点）

不跟 Cursor/Trae 拼 IDE 体验，不跟 Claude Code 拼终端能力，而是主打：
- **服务器端常驻** — 长程任务不被关机打断
- **Web 即开即用** — 无需安装，任何设备访问
- **团队协作原生** — 不是插件，是平台核心
- **文科生友好** — 降低编程门槛的差异化定位

### 2. 借力国产替代叙事

- Cursor 对中国断供 → 国产替代紧迫性
- 代码上传国外服务器 → 数据主权风险
- 闭源商业工具 → 开源自主可控

### 3. 学术背书

- 计算语言学 + 语言哲学 + AI 哲学的跨学科背景
- SFGS、CDM、Vibe Ability 等研究成果
- 将"语言理解"与"代码生成"建立理论联系
